# 笔记本同步

VNote 没有内置的云账户，这是有意为之的设计。由于笔记本就是一个装着纯文件的普通目录，你可以用任何你早已信任的服务或工具来同步它——并始终完全掌控自己的数据。这一理念背后的思考参见[为什么选择 VNote](../getting-started/why-vnote.md)。

## 同步的原理

一个笔记本完全包含在它的**笔记本根文件夹**中：笔记、图片、附件和配置全都在其中。要同步一个笔记本，你同步的就是这个文件夹。没有需要协调的中央数据库——文件系统*本身*就是唯一可信来源。

一般模式如下：

1. 把笔记本根文件夹放进由同步工具管理的目录中。
2. 在每台电脑上，把该文件夹**导入**为笔记本（参见[导入与迁移](importing-migrating.md)）。
3. 照常编辑；同步工具会在机器之间传播文件改动。

## 文件夹同步服务

**Dropbox**、**OneDrive**、**Nextcloud**、**Google Drive** 等服务，或任何文件夹同步工具，都能很好地工作。在每台机器上把笔记本放在被同步的目录中，让服务去搬运文件。这是最简单的方案，无需额外工具。

!!! tip "编辑前让同步先完成"
    切换机器时，先给同步客户端一点时间完成下载，再开始编辑。在改动同步完成之前，同时在两台机器上编辑同一个笔记本，正是导致冲突的原因。

## 用 git 做版本控制

若需要完整的历史和精细的控制，可用 **git** 跟踪笔记本。由于笔记是纯文本，git 能给出有意义的逐行差异，你也就拥有了一份完整、可回退的知识库历史。在笔记本根文件夹中初始化仓库，随时提交，并推送到任意你喜欢的远端。

如果两台机器出现分叉，git 还提供显式的冲突处理——相比文件夹同步的静默合并，一些用户更青睐这种方式。

## 避免与解决冲突

- **会话前后都同步。** 开始前确保笔记本是最新的，离开前让改动上传完成。
- **不要在两台机器上同时编辑同一篇笔记。** 当同一个文件在同步前于两处被改动，就会发生冲突。
- **一旦发生冲突，** 同步工具通常会保留两个版本（例如一个「冲突副本」文件）。在 VNote 中打开两者，手动合并内容，然后删除多余的文件。使用 git 时，像处理任何文本文件那样解决冲突即可。

## 哪些内容会被同步

笔记本根文件夹之下的一切，包括 VNote 的每笔记本索引和配置，都属于该笔记本，应当一起同步。应用级别的设置单独保存在 VNote 的[配置文件夹](../customization/settings.md)中，不属于任何笔记本——只有当你也想在机器间携带应用设置时，才需要同步它们。
